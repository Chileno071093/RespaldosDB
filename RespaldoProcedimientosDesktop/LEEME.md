# Respaldo de objetos SQL

Proyecto VB.NET Windows Forms para Visual Studio 2022 y .NET Framework 4.8.

Usa el paquete NuGet `Microsoft.Data.SqlClient`; Visual Studio lo restaura al compilar (desde la línea de comandos: `msbuild /restore`).

Abra `RespaldoProcedimientosDesktop.sln` en Visual Studio. Complete servidor, base de datos, usuario y password de SQL Server. Elija la carpeta con los archivos `.sql` y la carpeta donde desea guardar el respaldo. Pulse **Analizar** para ver los objetos antes de crear archivos. Marque los que desea guardar y pulse **Respaldar seleccionados**. El botón **Comparar** muestra la definición actual junto con la declaración del archivo y una comparación por líneas (algoritmo de Myers, el mismo de `git diff`), con números de línea, eliminaciones en rojo y agregados en verde. Por defecto oculta los tramos iguales y deja 3 líneas de contexto; **Mostrar el objeto completo** los despliega. La comparación ignora los comentarios previos al `CREATE` (SQL Server los guarda en la definición), la diferencia entre `CREATE`, `ALTER` y `CREATE OR ALTER` (SQL Server guarda un `ALTER` como `CREATE`), las mayúsculas y `PROC`/`PROCEDURE` del encabezado, y los espacios al final de línea. **Ignorar diferencias de espacios y tabulaciones** también ignora cambios de indentación. **Cancelar** detiene la operación activa de análisis, búsqueda o respaldo; si ya terminó, el botón queda deshabilitado. Durante el respaldo se escriben primero archivos temporales, que se limpian si se cancela antes de crear la carpeta final.

La aplicación recuerda servidor, base de datos, usuario, carpetas y opciones entre sesiones; se guardan al analizar y al cerrar la ventana en `%APPDATA%\RespaldoObjetosSQL\configuracion.xml`. El password nunca se guarda. Para volver a los valores iniciales, borre ese archivo.

El usuario y el password se envían con `SqlCredential` (el password como `SecureString`), no dentro de la cadena de conexión, y se liberan al terminar cada operación. **Cifrar conexion** (activada por defecto) exige cifrado TLS. **Confiar en el certificado del servidor** (activada por defecto) acepta certificados autofirmados, habituales en servidores internos: la conexión va cifrada, pero no se valida la identidad del servidor. Si el servidor tiene un certificado válido, desmarque esa opción para validarlo.

Para ubicar objetos en otras bases del mismo servidor, seleccione una o varias filas de la vista previa con Ctrl/Shift y pulse **Buscar en bases**. La búsqueda revisa las bases de usuario en línea y accesibles para el login SQL. Muestra base, tipo, esquema y nombre; desde el resultado puede usar una base como nueva base de análisis. Esta consulta no cambia ni respalda las otras bases. Los catálogos solo muestran los objetos para los que el usuario tiene visibilidad, por lo que la ausencia de una coincidencia no demuestra que el objeto no exista.

Durante **Buscar en bases**, la aplicación muestra la base que está revisando y el avance (por ejemplo, 3/20). El resultado muestra el tiempo de cada base y los errores de las bases omitidas. Pulse **Cancelar** para detener el recorrido; si hay una consulta en curso, solicita su cancelación. La conexión tiene un límite de espera configurado en 5 segundos y cada consulta de búsqueda, en 10 segundos, por lo que la cancelación puede tardar un poco en reflejarse. Si la versión anterior de la aplicación se queda detenida, cierre la ventana y abra la solución actualizada en Visual Studio.

La aplicación lee el contenido de cada archivo `.sql` y reconoce declaraciones `CREATE`, `ALTER` y `CREATE OR ALTER` de procedimientos, vistas, triggers y funciones. Usa el nombre declarado dentro del SQL, sin depender del nombre del archivo. Luego consulta en la base indicada sólo las definiciones de los nombres detectados; antes de respaldar vuelve a consultar sólo los nombres seleccionados. La opción **Incluir subcarpetas** permite buscar también en `Interfaz` al seleccionar la carpeta principal. Los archivos se leen respetando su BOM (UTF-8, UTF-16, UTF-32); si no tienen BOM se intenta UTF-8 y, si no es válido, se usa la codificación ANSI de Windows (por ejemplo, Windows-1252), de modo que la `ñ` y los acentos se conservan. Si el mismo objeto está declarado en más de un archivo, la columna **Archivo** muestra `(+N)`, el detalle enumera los otros archivos y **Comparar** agrega una pestaña de diferencias por cada archivo.

Durante **Buscar en bases** se usa una sola conexión y se cambia de base con `ChangeDatabase`, en lugar de abrir una conexión (y un login) por cada base.

Antes de escribir, la aplicación vuelve a consultar SQL Server y detiene el respaldo si alguna definición seleccionada cambió desde la vista previa. También comprueba que no hayan cambiado los archivos `.sql` de los objetos seleccionados (incluidos los archivos duplicados); los cambios en otros archivos no bloquean el respaldo. Cada ejecución crea una carpeta con fecha y hora dentro del destino, con subcarpetas `Procedimientos`, `Vistas`, `Triggers` y `Funciones`. Cada archivo respaldado termina en `_<nombre de la base>.sql`, por ejemplo `[Reporte].[P_Ejemplo]_AdministradorEmpleado_PEMSACELAYA.sql`. Los archivos `.sql` y los reportes `.txt` se guardan en UTF-16 LE con BOM y saltos de línea CRLF. Se agrega un `.editorconfig` que configura tabulaciones para los `.sql` en editores compatibles; la indentación del cuerpo de cada objeto se conserva tal como la devuelve SQL Server. `Declaraciones_detectadas.txt` muestra qué objeto se leyó de cada archivo. `Objetos_no_respaldados.txt` muestra los omitidos por estado o selección. `Archivos_sin_objetos.txt` enumera archivos sin declaraciones reconocidas. `Verificacion.txt` registra los archivos SQL verificados y su SHA-256. La aplicación no ejecuta los scripts de origen ni modifica objetos en SQL Server.

Cuando un objeto no aparece en el catálogo con el usuario usado, la aplicación muestra **No visible o inexistente**: esas situaciones no se pueden distinguir de forma fiable con esas mismas credenciales. Si el catálogo muestra el objeto pero no entrega su definición, se informa por separado como **Sin definicion**.

El proyecto compila con Visual Studio 2022. El análisis, el respaldo y la búsqueda en bases se probaron contra LocalDB mediante un arnés de pruebas, incluido un login SQL con `SqlCredential`; falta probarlos en el servidor real.
